When something doesn't work, here's how to diagnose it. Most problems are a
missing optional dependency or a path that needs setting.

* First steps
- *Read the messages.* Switch to the =*Messages*= buffer (=C-h e=, or =C-x b
  *Messages*=) to see warnings and errors, including anything that failed at
  startup.
- *Cancel and retry.* If a command seems stuck, press =C-g= and try again.
- *Reload the config.* After editing =config.org=, =C-c p R= reloads it without
  restarting Emacs.

* The agenda is empty
- Check which *vault* is open — its name is at the top left of the file tree.
  Switch with =C-c p V V= (see [[file:Vaults.org][Vaults]]). Every =.org= file under the vault is
  scanned, at any depth (see [[file:Planning-setup.org][Planning setup]]) — except =Journal/=, =Archive/=,
  dotted folders, =init.org= and =workspace.org=.
- If you've turned on *file-set filtering* (=C-c p g=), the agenda only shows the
  active set — toggle it off to see everything.
- If it went empty part-way through a session, check =custom.el= in your config
  folder for a saved =org-agenda-files= line and delete it. The agenda list is
  computed from your Org folder on every build, so a value saved there is stale
  by definition; older versions could end up saving one. Restart afterwards.

* Icons look like boxes or are missing
- The *Material Symbols Outlined* font isn't installed, or the wrong variant is.
  Install the plain "Regular" static file per [[file:Installation.org][Installation]]. The file tree falls
  back to simple folder/file icons without it.
- Files show the generic icon until you map categories in =workspace.org= — see
  [[file:Customization.org][Customization & appearance]].

* Spell check isn't underlining anything (or errors on startup)
- It needs the =enchant= library plus a dictionary per language. If =enchant=
  isn't installed, typo checking simply stays off and the rest of the config
  loads normally. Install it per [[file:Installation.org][Installation]].
- Words valid in /any/ of your configured languages aren't flagged by design.
  Check =ps/typo-languages= matches what you write in.
- List the dictionaries =enchant= can see: =enchant-2 -list-dicts=.

* A theme didn't load
- Built-in themes (=modus-*=) always work. Package themes install automatically
  on first load, which needs network access the first time. Check =*Messages*=
  for a download error, then retry.

* Startup fails or behaves oddly
- Run from a *clean copy* to isolate the problem without risking your files or
  Git history: =./scripts/run_emacs_dev.sh --sandbox= (see [[file:Developing.org][Developing &
  extending]]). If it works there, the issue is in your =local.el= or Org data.
- Launch with =emacs --debug-init= to get a backtrace on startup errors.

* The mouse pointer jumps to the corner of the frame
Ediff moves the physical mouse pointer by itself — into its control panel when
a comparison starts, and to the top-left of the frame when one ends. That is
what you see when an AI-assistant diff opens or closes. This config turns it
off by setting =ediff-grab-mouse= to =nil= (see [[file:AI-integration.org][AI integration]]); set it back to
=t= for the stock behaviour.

* The mouse pointer stops changing shape
The pointer stays an arrow everywhere: no pointing hand over links in your Org
files or over entries in the file tree, and no resize arrows over the dividers
between windows. Clicking and highlighting still work, so it looks like links
have broken — but nothing is wrong with the links, and every window is affected
at once. It starts after dragging a divider to resize windows, and once it
starts it used to last until you restarted Emacs.

This now clears itself: the pointer comes back as soon as you press a key or
run any command. If you ever see it persist beyond that, restarting Emacs
restores it.

* "Conflicted copy" files keep appearing
Your vault is in a cloud folder (Dropbox and the like) as well as in Git, and
the two are both syncing the hidden =.git= folder. Sooner or later that breaks
Git outright — =fatal: bad object= — and the sync indicator says
=conflicted copies inside the repository=. It is *not* a merge conflict and
there is nothing to resolve in Magit.

[[file:Dropbox-and-git.org][Dropbox & Git together]] has the cleanup and the one-time fix that stops it
recurring.

* A file I edited on my phone lost its changes (or mine did)
It should not: when a file changes on disk while you have unsaved edits in
Emacs, neither version is written over the other. The file is listed in *Show
Files Out of Sync* (Productivity → Sync & Version Control) so you can compare
the two and choose — see [[file:Sync-and-backups.org][Sync & backups]].

* Git sync did something unexpected
- Open =C-x g= (Magit) to inspect the repository state and history.
- Pause sync with =C-c p s= while you sort things out.
- If the indicator looks stuck on "Syncing", it recovers on its own within a
  minute or so; toggling sync off and back on with =C-c p s= forces an immediate
  recovery and resync.

* Still stuck?
Open an issue with what you tried, the relevant lines from =*Messages*=, your
Emacs version (=M-x emacs-version=), and your OS.
