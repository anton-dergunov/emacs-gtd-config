#+TITLE: AI integration (Claude Code)
#+OPTIONS: toc:t
#+STARTUP: inlineimages

[[file:Index.org][↑ Back to the documentation index]]

An optional AI assistant runs in a side window and can read and edit your Org
notes, with its proposed changes shown to you as Emacs diffs. It runs on your
Claude Pro/Max subscription. This page is a brief overview; more detail will
follow.

* Opening it
Press =C-c c= to start or toggle the assistant (Productivity menu → /Claude
Code — start/toggle/). =C-c c m= opens its menu, =C-c c s= stops the session.

It opens in a stable side panel rather than taking over whatever you're
editing — docked to the right when your Emacs window is wider than it is
tall, or to the bottom when it's taller than wide (e.g. a window positioned
on the narrow edge of an ultrawide monitor). The side is recomputed each time
you open it, so it adapts if you've resized or moved the window since.

* What it can see
The assistant is aware of the file you are looking at and the text you have
selected in your Org files — select a few lines and ask about "this", and it
knows what you mean. It can also open files, show you diffs, and report Emacs
diagnostics.

The usual flow works as you would expect it to: select some lines, click into
the assistant's window, and ask. What it receives is the file's name, the line
numbers, and the selected lines themselves. Two details are worth knowing:

- *It is sent once, not with every message.* Asking a follow-up without going
  back to your file does not attach the same lines again — they are already
  part of the conversation. Selecting something else and returning to the
  assistant sends the new selection.
- *Very large selections are not pasted in.* Past =ps/claude-selection-max-lines=
  (500) or =ps/claude-selection-max-chars= (20000), only the file is reported
  and the assistant reads it itself.

With nothing selected, it is simply told which file you are in — including
right after you start a session, so the first question can say "this file".

If it ever answers that it cannot see your selection, set
=ps/claude-debug-selection= to =t=, reproduce it once, and look at the log named
by =ps/claude-debug-resize-file=: it records every selection sent and every one
skipped, with the reason.

* Reviewing proposed edits
Changes the assistant wants to make are shown as an Emacs diff (Ediff) so you
can step through them and accept or reject. Your mouse pointer is left where
you put it — out of the box, Ediff physically moves the pointer to the corner
of the frame when a diff closes, which is disabled here.

To get the stock behaviour back, set =ediff-grab-mouse= to =t=.

** Under the hood
Settings block: =config.org= → /AI Assistant → Ediff: don't move the mouse
pointer/ — =ediff-grab-mouse=.

* Telling it how to work with your notes
The assistant reads a file named =AGENTS.md= in your Org directory (with a tiny
=CLAUDE.md= alongside that just points to it). That file tells the assistant that
words like "task", "project", and "note" mean entries in /your/ Org files — so
when you say "add a task", it edits your plans rather than inventing its own list.

You can open and edit =AGENTS.md= to tune how the assistant behaves. It is yours
alone — nothing here ever writes to it. If you keep your notes in your own
directory (not the bundled sample), put your own =AGENTS.md= there.

** The generated context file
Two things the assistant needs are kept up to date for you, in a companion file
that =AGENTS.md= points at: =.claude/generated-context.md= in your Org directory.

- *The conventions in force* — your TODO keywords, priorities, tags, whether
  finishing a task logs a timestamp, and where the journal lives. These come from
  =config.org=, so the assistant is told what you actually use instead of guessing
  from what it happens to read.
- *Your context tags and situations* — when you declare them (see
  [[file:Situations.org][Situations]]), two tables: what each tag promises, and which saved search each
  one feeds. Generated from the same declaration the tag picker and the menus
  use, so it cannot drift — and it means you never have to describe your tags a
  second time in =AGENTS.md=.
- *An index of your plan files* — one line per file, taken from that file's
  =#+SUBTITLE:=. It lets the assistant route something to the right file without
  opening all of them. Files with no =#+SUBTITLE:= are simply left out, so writing
  one is how you describe a file's purpose.

It is rebuilt when Emacs starts, when you reload the configuration (=C-c p R=),
and a couple of seconds after you save any plan file — so a subtitle you just
edited, or a file you just created, shows up right away. =M-x ps/ai-context-sync=
rebuilds it on demand. The file is rewritten only when something actually
changed, and since it is regenerated from scratch every time, you can safely
exclude it from version control.

Don't edit it: your changes are overwritten. Change =config.org= or the relevant
file's =#+SUBTITLE:= instead.

** Under the hood
Module: =lisp/ps-ai-context.el=. Settings block: =config.org= → /Package
Management → AI context sync (ps-ai-context.el)/ — =ps/ai-context-enabled=,
=ps/ai-context-file=, =ps/ai-context-next-keyword=,
=ps/ai-context-save-debounce=.

* Copying text from the assistant window
The live session is an interactive terminal, so a normal mouse selection there
gets cleared as the assistant keeps drawing. Two reliable ways to copy:

- Select text and press =M-w= (=Option-W= on macOS) right away to copy it.
- Press =C-c C-e= to switch the session window to a plain, read-only view where
  selection, scrolling back, and the Edit → Copy menu all work normally; press
  =C-c C-j= to return to the interactive view.

* When a file was changed both on disk and by you
If you edit a file in Emacs and something else (the assistant, Git sync, another
program) also changes it on disk, Emacs will ask before discarding your edits.
To compare your buffer against what is on disk, run =M-x ediff-current-file=
(or =M-x diff-buffer-with-file= for a quick diff), then decide whether to keep
your version or reload.

This only applies when you have /unsaved/ edits. If the buffer matches what you
last saved, it simply refreshes to the new content without asking — see
[[file:Sync-and-backups.org][Sync & backups]].

* If the assistant window looks wrong after resizing
The session window is a terminal, and resizing it makes the assistant redraw
its whole display. If it ever ends up showing blank space, missing text at the
top, or content that stops part-way down, resizing it again (or scrolling)
redraws it correctly.

Dragging the divider repaints the panel continuously, so it may flicker while
you drag. =ps/claude-resize-throttle-interval= (in =config.org= → /Package
Management → Claude Code/) controls how often it repaints mid-drag — raise it
for less flicker, lower it for closer tracking as you drag.

Lines in the panel are never wrapped: it is a terminal, and the assistant has
already broken its output to fit the width. A few of the symbols it draws
(the =⏺= bullet before each step, the =⎿= under it, the =⏵⏵= in the footer)
have no monospace form in any installed font and are drawn a little wider than
one character cell, so a line filling the full width can overhang the right
edge by a few pixels. Those pixels are clipped. Letting them wrap instead used
to cost a whole screen line each, which pushed the bottom of the panel out of
sight and left blank bands and half-painted screens behind — the thing a
manual resize appeared to "fix".

If the panel still misbehaves, set =ps/claude-debug-resize= to =t=, reproduce
the problem once, and inspect the log named by =ps/claude-debug-resize-file=.

* Quitting Emacs with a session running
Emacs normally asks to confirm before killing running processes, which a live
assistant session would trigger. It quits without asking instead; set
=ps/claude-no-exit-prompt= to =nil= to get the confirmation back.
