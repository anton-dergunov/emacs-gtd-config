#+TITLE: AI integration (Claude Code)
#+OPTIONS: toc:t
#+STARTUP: inlineimages

[[file:Index.org][↑ Back to the documentation index]]

An optional AI assistant runs in a side window and can read and edit your Org
notes, with its proposed changes shown to you as Emacs diffs. It runs on your
Claude Pro/Max subscription. This page is a brief overview; more detail will
follow.

* Opening it
Press =C-c c= to start or toggle the assistant (Productivity menu → /Claude
Code — start/toggle/). =C-c c m= opens its menu, =C-c c s= stops the session.

It opens in a stable side panel rather than taking over whatever you're
editing — docked to the right when your Emacs window is wider than it is
tall, or to the bottom when it's taller than wide (e.g. a window positioned
on the narrow edge of an ultrawide monitor). The side is recomputed each time
you open it, so it adapts if you've resized or moved the window since.

* What it can see
The assistant is aware of the file you are looking at and the text you have
selected in your Org files — select a few lines and ask about "this", and it
knows what you mean. It can also open files, show you diffs, and report Emacs
diagnostics.

* Telling it how to work with your notes
The assistant reads a file named =AGENTS.md= in your Org directory (with a tiny
=CLAUDE.md= alongside that just points to it). That file tells the assistant that
words like "task", "project", and "note" mean entries in /your/ Org files — so
when you say "add a task", it edits your plans rather than inventing its own list.

You can open and edit =AGENTS.md= to tune how the assistant behaves. If you keep
your notes in your own directory (not the bundled sample), put your own
=AGENTS.md= there.

The block near the bottom of =AGENTS.md= (between the =ps-generated= markers) is
auto-generated from =config.org='s settings — your TODO keywords, priorities, and
similar facts — and is overwritten on the next reload, so edit =config.org= to
change those; the rest of =AGENTS.md= is yours to edit freely.

* Copying text from the assistant window
The live session is an interactive terminal, so a normal mouse selection there
gets cleared as the assistant keeps drawing. Two reliable ways to copy:

- Select text and press =M-w= (=Option-W= on macOS) right away to copy it.
- Press =C-c C-e= to switch the session window to a plain, read-only view where
  selection, scrolling back, and the Edit → Copy menu all work normally; press
  =C-c C-j= to return to the interactive view.

* When a file was changed both on disk and by you
If you edit a file in Emacs and something else (the assistant, Git sync, another
program) also changes it on disk, Emacs will ask before discarding your edits.
To compare your buffer against what is on disk, run =M-x ediff-current-file=
(or =M-x diff-buffer-with-file= for a quick diff), then decide whether to keep
your version or reload.

* If the assistant window looks wrong after resizing
The session window is a terminal, and resizing it makes the assistant redraw
its whole display. If it ever ends up showing blank space, missing text at the
top, or content that stops part-way down, resizing it again (or scrolling)
redraws it correctly.

Dragging the divider repaints the panel continuously, so it may flicker while
you drag. =ps/claude-resize-throttle-interval= (in =config.org= → /Package
Management → Claude Code/) controls how often it repaints mid-drag — raise it
for less flicker, lower it for closer tracking as you drag. While you drag,
long lines are clipped at the right edge instead of wrapping; normal wrapping
returns as soon as you release.

If the panel still misbehaves, set =ps/claude-debug-resize= to =t=, reproduce
the problem once, and inspect the log named by =ps/claude-debug-resize-file=.

** Under the hood
Module: =lisp/ps-claude.el=. Settings block: =config.org= → /Package Management
→ Claude Code (ps-claude.el)/ — =ps/claude-window-width=,
=ps/claude-resize-debounce-delay=, =ps/claude-reanchor-delay=,
=ps/claude-resize-throttle-interval=, =ps/claude-no-exit-prompt=,
=ps/claude-debug-resize=.

* Quitting Emacs with a session running
Emacs normally asks to confirm before killing running processes, which a live
assistant session would trigger. It quits without asking instead; set
=ps/claude-no-exit-prompt= to =nil= to get the confirmation back.
