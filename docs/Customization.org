This config is meant to be made yours. This page collects the taste-based
choices — colors, fonts, icons, languages — and points to where every setting
lives. (Settings that shape the *planning view* itself, like the agenda
sections and the mode line, are covered in [[file:Agenda.org][The Agenda]].)

* Where settings live
There are two layers, modelled on an editor's *User* vs *Workspace* settings:

- =config.org= — the shared, public configuration. Its /Settings/ section
  (right after the bootstrap) is the single place to adjust defaults: there's a
  block per feature (Appearance, Availability, Conflicts, Mode line, Task
  count, Material icons, File Tree, …).
- =workspace.org= — settings tied to /your/ Org data folder (your category
  icons, your file-tree sets). It lives beside your Org files, loads *after*
  =config.org=, and overrides it. This keeps your personal categories out of the
  public repo and means pulling upstream changes never conflicts with your
  customizations.

Open them from *Productivity → Config*: =C-c p C= opens =config.org= (=F10=
too), =C-c p W= opens =workspace.org=; the lower-case =C-c p R= / =C-c p w=
reload them. Copy =samples/realistic/workspace.org= as a starting point.

Every setting this config adds is a =ps/...= variable, so you can also browse
and change them with =M-x customize-apropos= → =^ps/= (or *Config → Customize
ps/ Settings* in the menu).

* Color theme
Switching the whole look is a one-line change. In =config.org=, /Settings →
Appearance/, set =ps/color-theme=:

#+begin_src elisp
(defvar ps/color-theme 'solarized-light  ; <- change this
  "Color theme loaded by `Editor & UI / Color theme'.")
#+end_src

External-package themes are *installed automatically* on first load.

theme-relative equivalents so it looks right on light /and/ dark backgrounds.

before you commit. Set =ps/color-theme= to keep it.

* Fonts
Fonts are set in =config.org= → /Settings → Fonts/, by *role* rather than one
font at a time:

| Setting               | Used for                                            |
|-----------------------+-----------------------------------------------------|
| =ps/font-mono=        | The editing font, and everything aligned in columns |
| =ps/font-prose=       | Running text (the =variable-pitch= face)            |
| =ps/font-size=        | Body text size, in points                           |
| =ps/font-prose-scale= | Size of running text relative to the body text      |

Each role is a *list* of font families in preference order, and the first one
your machine actually has is the one used. A family you don't have installed is
simply skipped, so you can name a font before installing it — or share the
config across machines — without anything breaking.

=ps/font-mono= has to be a monospaced font. It's not only the editing font: it
also defines the character width everything else is measured in, so the agenda,
the schedule ruler, and the availability and conflict reports all line their
columns up against it.

Sizes elsewhere follow =ps/font-size= automatically — headings, the line-number
gutter, and the category icons all scale with it, so changing that one number
resizes the whole interface.

Emoji and symbol characters your font doesn't cover are drawn from other fonts,
which can be slightly taller and make their line taller than the rest — so text
appears to shift as those characters scroll past or animate.
=ps/font-rescale-alist= scales those fallback fonts down so every line keeps the
same height. If some character still sits taller, add its font to that list with
a smaller factor. Those factors are tuned against a particular editing font, so
they're worth a second look if you change =ps/font-mono=.

#+begin_quote
Under the hood: =lisp/ps-fonts.el=; settings in =config.org= → /Settings →
Fonts (ps-fonts.el)/.
#+end_quote

* Reading width
Plan files wrap edge-to-edge on a maximized window, which reads better centred
in a column with margins — similar to Obsidian. This config does that with
=visual-fill-column=: text is capped at a maximum width and centred; the
margins shrink to zero once the window itself is narrower than that width, so
nothing is lost on a split screen or a small frame.

Margins only apply to actual plan/prose files — the same ones the agenda
scans — never to =config.org=, =workspace.org=, the journal/archive, or a
generated view (Agenda, Tasks, Calendar, Schedule/Timeline). They're also off
during the =F7= blank-line-recovery review, since a diff reads better at full
pane width.

Change the maximum width, in characters, in =config.org= → /Settings →
Reading width/ (=ps/prose-width-columns=); set it to =0= to turn margins off
entirely.

* Line numbers
Line numbers show in file buffers and in the Tasks view. In Org buffers they are
drawn smaller than the text and in a muted colour — the number on the line
you're editing included, which a theme would otherwise paint in the full body
text colour, making it the loudest thing on the page. The numbers stay readable
without competing with the prose; code buffers keep the ordinary gutter. Adjust
the size and the colour in =config.org= → /Settings → Line numbers/
(=ps/line-numbers-scale=, =ps/line-numbers-face=); a scale of =1= leaves them at
full size, and a face of =nil= leaves the colours alone.

The gutter reserves at least two columns and widens by itself for a longer file.
That minimum matters: sizing itself from scratch, the gutter grows and shrinks by
a column as you scroll, which nudges the numbers and the text sideways. Change
the minimum in =config.org= → /Editor & UI → Line numbers/, or set it to =nil=
there to let Emacs size the gutter freely.

* Category icons
Icons in the agenda and file tree come from the *Material Symbols Outlined* font
(install it per [[file:Installation.org][Installation]]). They're assigned *declaratively*, mapping a
=<Category>.org= file's basename to a [[https://fonts.google.com/icons][Material Symbols name]] — e.g.
=("Blog" . "edit_square")=.

=config.org= ships *no* mappings, so every file shows the generic =File= icon
until you provide a map. Do that in your =workspace.org= (so your categories stay
private):

- per file: =ps/material-icons-category-map= (=<Category>.org= → icon name);
- per folder: =ps/material-icons-folder-map= — the icon drawn for the *folder
  itself*, e.g. =("Current" . "calendar_month")=. Unmapped folders get a plain
  folder icon;
- for a folder's *contents*: =ps/material-icons-folder-contents-map= — one icon
  for every =.org= file under that folder, instead of listing them all.

Folder keys match a folder's name at any depth, or its path relative to the Org
base — so ="older"= icons every folder of that name, while ="ML/older"= icons
just the one. Category icons work the same wherever the file sits.

The mappings are read when the tree is built, so a file you create later in the
session shows the generic file icon rather than its category one until you run
=M-x ps/reload-workspace-config=.

See =samples/realistic/workspace.org= for a complete example. To fine-tune
size/alignment, adjust =ps/material-icons-height-scale= and
=ps/file-tree-icon-ascent= in =config.org= → /Settings/.

* File tree layout
All of these live in =config.org= → /Settings → File Tree/.

| Setting                            | What it does                                            |
|------------------------------------+---------------------------------------------------------|
| =ps/file-tree-hide-root=           | don't name the Org directory at the top (default on)    |
| =ps/file-tree-top-level-spacing=   | gap above each top-level folder, in fractions of a line |
| =ps/file-tree-bold-top-level=      | draw top-level folders bold, as section headers         |
| =ps/file-tree-order=               | explicit folder order; see below                        |
| =ps/file-tree-show-toggle-button=  | collapse/expand-all button in the top-right corner      |
| =ps/file-tree-follow-current-file= | highlight the file you're editing                       |
| =ps/file-tree-root-mode=           | =single= (one tree) or =subdirs= (a root per folder)    |
| =ps/file-tree-ignored-files=       | names never shown in the tree                           |

** Ordering the folders
By default entries are alphabetical. =ps/file-tree-order= overrides that: names
listed before the =:rest= keyword are pinned to the top in that order, names
after it are pinned to the bottom, and everything unlisted fills the middle
alphabetically. A name matches an entry by its file name, its name without the
=.org= extension, or its path relative to the Org base — the same matching the
icon maps use. Put it in your =workspace.org=:

#+begin_src elisp
(setq ps/file-tree-order '(:rest "Current" "Vision"))
#+end_src

Treemacs always draws folders before loose files, so "bottom" means the bottom
of the *folder* list: files sitting directly in your Org directory still come
after every folder, whatever this says.

** What the file sets hide
Two different lists decide what you see. =ps/file-tree-ignored-files= is about
*display* — it hides =init.org=, =workspace.org=, =AGENTS.md=, =CLAUDE.md=,
dotfiles and build artifacts from the tree. What the *agenda* reads is a
separate question, answered by =ps/org-files-exclude-directories= and
=ps/org-files-exclude-files= (see [[file:Planning-setup.org][Planning setup]]). A file can be in one list
and not the other: your journal is scanned out of the agenda but still browsable
in the tree.

* Live markup preview while editing
Org markup — =*bold*=, =/italic/=, =_underline_=, =+strikethrough+=, =code=,
=~verbatim~=, link brackets, entities like =\alpha=, and sub/superscripts like
=x_1= — renders clean, with the markup symbols hidden, like a live preview.
Move point onto a marked-up bit of text and the raw syntax reappears so you
can edit it; move away and it hides again. This applies everywhere except the
read-only documentation viewer (these pages), which always keeps markers
hidden since you're not editing there.

While you type the leading stars of a new heading, they show exactly as typed
(=*=, =**=, =***=) — plain, never bold, and without disturbing the bullet on the
next heading; the fancy bullet appears once the heading is complete (after the
space). Typing an unterminated =*= in a heading's text likewise leaves the next
heading's bullet intact until you close it.

* Where headline tags sit
Tags appear exactly where you typed them. Whatever spacing stands between the
headline text and the first =:= in the file is the spacing you see — one space,
or five, or a whole column of them:

#+begin_example
** TODO Write the proposal :work:writing:
#+end_example

Nothing re-spaces a headline behind your back. Org's own default is to pad every
tagged headline out to a fixed column, rewriting the line as you type on it, as
you set tags, and as you promote or demote it; that is switched off here, so
your files keep the spacing you gave them.

When a headline is too long for the window, the tags move to the next line
*together* — the group is never split, and no stray coloured fragment is left
behind at the right edge.

One side effect of how that is done: a literal no-break space typed into an Org
file is no longer highlighted the way Emacs highlights it elsewhere.

* Typo / spell checking
Org buffers get a quiet, multilingual typo checker. A word is underlined with a
subtle wavy line *only when none of your configured languages recognise it*, so
terms valid in any language you write in are never flagged (e.g. Spanish =calor=
or Cyrillic words inside English text stay clean). Code, links, file paths, and
=verbatim=/=~code~= markup are skipped. Press =M-$= on an underlined word to pick
a correction or add it to your personal dictionary. Only individual words are
checked — no grammar checking, no network/LLM use.

The accepted languages default to English, Russian, and Spanish. Edit
=ps/typo-languages= in =config.org= → /Settings → Typo / spell checking/ to match
the languages you write in. Typo checking runs only in editable Org files —
these documentation pages, which open read-only, are never spell-checked.

This uses [[https://github.com/minad/jinx][Jinx]], which needs the =enchant= library plus a dictionary per
language (see [[file:Installation.org][Installation]]). On macOS, English works out of the box via the
system speller; for stricter checking or for Russian, install Hunspell
dictionary files (=<locale>.aff= / =<locale>.dic=) into
=~/.config/enchant/hunspell/=. List what =enchant= can see with =enchant-2
-list-dicts=. Dictionaries are available from the [[https://github.com/LibreOffice/dictionaries][LibreOffice dictionaries]] repo.
If =enchant= isn't installed, the rest of the config still loads — typo checking
just stays off.

The design rationale is in =design-docs/typo-checker.md=.

* Under the hood / Customize
- Reading-width margins: =lisp/ps-prose-width.el= (uses the =visual-fill-column=
  package), wired in =config.org= → /Org Mode → Appearance → Reading width
  margins/; settings in =config.org= → /Settings → Reading width/
  (=ps/prose-width-columns=).
- Theme machinery and live preview: =config.org= → /Editor & UI/
  (=ps/color-theme=, =ps/preview-theme=).
- Line-number gutter width: =config.org= → /Editor & UI → Line numbers/
  (=display-line-numbers-width=).
- Line-number size and colour in Org buffers: =lisp/ps-line-numbers.el=, wired in
  =config.org= → /Editor & UI → Line numbers/; settings in =config.org= →
  /Settings → Line numbers/ (=ps/line-numbers-scale=, =ps/line-numbers-face=).
- Live markup preview: the =org-appear= package, wired in =config.org= →
  /Appearance → Show formatting markup only at point/.
- Literal heading stars while typing: =lisp/ps-heading-stars.el=, wired in
  =config.org= → /Appearance → Keep heading stars visible while typing them/.
- Material icons: =lisp/ps-material-icons.el= (+ =ps-agenda-icons.el=,
  =ps-file-tree-icons.el=); settings in =config.org= → /Material icons/ and
  /File Tree/.
- Typo checker: =lisp/ps-typo.el=; settings in =config.org= → /Typo / spell
  checking/.
- Headline tags kept whole when a line wraps: =lisp/ps-tags.el= (no settings);
  Org's own re-spacing is switched off in =config.org= → /Org Mode → Appearance/
  (=org-auto-align-tags=).
- Org markup in agenda lines: =lisp/ps-emphasis.el=, used by
  =ps-agenda-layout.el= and =ps-schedule-view.el= (no settings).
