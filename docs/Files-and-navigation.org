This page covers moving around your Org files: the file tree, named file sets,
scoping the agenda, window management, and quick jumps.

* The file tree
A sidebar tree of your Org folders and files, with the same category icons used
in the agenda.

- Toggle it with =F8= (Productivity → Layout & Navigation → Toggle File Tree),
  or =M-x ps/file-tree-toggle=.
- Click a file's *name* to open it; click a folder to expand/collapse it.

The tree shows the contents of your Org base directory directly — the directory
itself is not named at the top. Files sitting at the top level are visible and
subfolders nest to *any depth*. Top-level folders are drawn bold with a blank
strip above each, so the tree still reads as sections. The strip belongs to
neither neighbour, so the current-line highlight never bleeds into it. Note that folders are
listed before loose files, so anything sitting at the top level appears at the
bottom. Every folder gets an icon of its own, and you can give a particular
folder its own icon — see [[file:Customization.org][Customization & appearance]].

The tree stays current on its own in the situations that matter most: it
refreshes after a =git-sync= pull brings in anything, and it notices files and
folders appearing or disappearing on disk — including a file added or removed
from outside Emacs, say from Finder. Only folders you have expanded are
watched, so a change deep inside a folder that is currently closed shows up
the next time you open it. Use the manual refresh button below if the tree
ever looks behind.

Config files that live beside your notes — =init.org=, =workspace.org=,
=AGENTS.md=, =CLAUDE.md= — are hidden. That is a display choice only, separate
from what the agenda scans; both lists are described in
[[file:Customization.org][Customization & appearance]].

** Following the file you're editing
The tree highlights whichever file you are editing, so the two never disagree.
It only ever moves the highlight: it never expands a folder, never re-roots, and
never scrolls to somewhere you weren't looking. If what you're editing has no
entry in the tree — it isn't a file, or it's hidden, filtered out by a file set,
or inside a folder you collapsed — the highlight is *removed*, rather than left
pointing at something you aren't editing. It reappears as soon as you click or
move in the tree. Turn the whole thing off with
=ps/file-tree-follow-current-file=.

If the Material Symbols font isn't installed, files fall back to simple
folder/file icons — see [[file:Installation.org][Installation]] and [[file:Customization.org][Customization & appearance]].

** Browse a file's outline in the tree
The tree isn't just files and folders — you can drill into a file's *headings*
without opening it first. Where you click matters:

- Click a file's *icon* (not its name) to *expand* the file, listing the Org
  headings inside it. You can keep drilling into sub-headings the same way, so
  the tree mirrors the file's outline.
- Click any *heading* to open the file and jump straight to that heading.
- Click a file's *name* to just open the file.
- *Shift-click* any node (or click a folder) to toggle expand/collapse.

This makes the file tree double as a table of contents for navigating large Org
files.

* File sets
A *file set* is a named subset of your Org files — for example "Work" or
"Personal" — so you can focus on a slice of everything at once.

- =C-c p F= (Layout & Navigation → Cycle File Set) cycles through your defined
  sets, switching what the file tree shows.
- =C-c p g= (File Set Restricts Agenda) toggles whether the active set also
  *scopes the agenda* — when on, the agenda only includes tasks from the files
  in the current set. Turn it off to always see everything.

While a set is active, folders it has emptied disappear too, rather than
lingering with nothing under them. Under "All" — which filters nothing — a
folder that is genuinely empty on disk still shows.

File sets are defined per Org folder in =workspace.org= — see
[[file:Customization.org][Customization & appearance]].

* The vault name
The name at the tree's top left is the *vault* you are in — the folder all of
this is showing. Click it for a drop-down of your vaults and switch between
them, or add and remove them. It is kept short so it stays out of the way; if a
name is cut off, widen the limit with =ps/vault-chip-max-width=. See [[file:Vaults.org][Vaults]].

* Collapsing the whole tree
A small button in the tree's top-right corner collapses everything, and turns
into an expand button once it has. =M-+= and =M--= inside the tree do the same
from the keyboard. Hide the button with =ps/file-tree-show-toggle-button=.

* Refreshing the tree
A second small button, just left of the collapse/expand button, fully
re-renders the tree and re-applies the active file set's filters — a manual
fallback alongside the automatic refresh described above, useful right after
editing =workspace.org= or when you just want to be sure the tree matches
disk. It has no keyboard equivalent; click it, or use Productivity → Layout &
Navigation → Refresh File Tree.

* Resizing the tree
Drag the divider along the tree's right edge to make it wider or narrower.

That width then stays where you put it. Resizing the *Emacs window* — dragging
its border, maximising it, going full screen — hands the space it gains or loses
to whatever you are editing and leaves the tree at the width you chose, so the
tree only ever changes width when you drag it yourself. Hiding the tree with
=F8= and bringing it back reopens it at that same width.

The width the tree first opens at is =treemacs-width= in =config.org=.

* Window management
| Key               | Action                              |
|-------------------+-------------------------------------|
| =C-x 1=           | focus: keep only the current window |
| =C-x 2= / =C-x 3= | split horizontally / vertically     |
| =C-x 0=           | close the current window            |
| =C-x o=           | switch focus to the other window    |

This config also adds =C-x |= (also =C-c p |=, =ps/window-split-toggle=) to flip
a split between horizontal and vertical — handy when the agenda and a file end
up stacked the wrong way round. It only ever toggles your two regular windows;
the file tree and the [[file:AI-integration.org][Claude Code]] side panel, if
open, are left exactly where they are.

* Going back
Every ordinary window keeps its own trail of where it has been, shown as =‹ ›=
at the left of its mode line. Click =‹= to return to what you were looking at
before, =›= to go forward again — the way a browser works. =C-c <left>= and
=C-c <right>= do the same from the keyboard.

Back is not the same as /up/: it retraces the places you actually opened, which
after a few steps is not the folder above you. Going back never adds a window,
however the one you are in was opened.

An arrow is dimmed when there is nothing that way, and hovering over a live one
names where it would take you. Each window has its own trail, so going back in
one does not disturb the other, and the file tree and the Claude Code panel have
none — a panel's buffer is the point of it.

* Opening a file that is not a plan
Emacs is used here for planning, so this configuration does not pretend to be
the right place to open anything: a PDF goes to macOS Preview, a video to the
system player, an HTML file renders as a *page* rather than as source, and
Markdown opens with a reading view like the one these documentation pages use.
Audio is declined outright, and anything else that is not text asks before it
opens — nothing is ever loaded as raw bytes.

Opening a file replaces what is in the window you opened it from, so walking
from a folder into a file and on into another one stays in one place. The
exception is a list you keep coming back to — the [[file:Info-triage.org][capture queue]] is the one — which
keeps its own window and opens what it lists in the pane beside it.

Inside a rendered page, =R= reduces it to just the article and =&= hands it to
your real browser. In a Markdown file with a table too wide for the window,
=C-c |= stops lines wrapping so the table stays whole and scrolls sideways.

The whole policy is one editable list, =ps/open-handlers=. See [[file:Info-triage.org][Info triage]] for
the table and for where to change it.

* Browsing a folder
Opening a folder (Productivity → Capture & Notes → Open Notes Folder, or any
folder link) lists it as an icon, a size and a name — folders first, then
files, and no =.DS_Store=. The =ls -l= columns are left out: permissions, link
count, owner and group answer a question from 1971, and the one thing they did
say usefully, file or folder, is now an icon rather than the colour of the
name. Sizes are shown for files only, since a folder's own size says nothing
about what is inside it.

Press =(= for the full =ls= listing whenever you do want it, and again to go
back.

Clicking a file opens it by the rules above; clicking a folder goes into it,
reusing the same window rather than opening a new one each time.

=..= at the top of the listing goes to the parent folder, and so does =^=. That
is a different move from =‹=, which retraces where you have been.

* What the window title says
The window title and the mode line name the file you are editing without its
=.org= extension, so =Work.org= simply reads /Work/.

When two open files share a name, that alone would be ambiguous, so the folder
is put in front: open =Personal/Inbox.org= and =Work/Inbox.org= together and
they read /Personal/Inbox/ and /Work/Inbox/. The prefix appears only while both
are open — close one and the other goes back to plain /Inbox/. If the folder
name is still not enough to tell them apart, as much of the path as it takes is
shown.

* The mode line outside your plans
A short name works for a plan, which you know by name. It does not work for
anything else: half a dozen captured items all call their notes =index.md=, and
what you need to know is which one you are reading. So every file that is /not/
part of your planning set names itself by its path instead, with =~= standing in
for your home folder, followed by how far through it you are:

: ~/info-triage-inbox/2026-08-16_167/index.md · 14%

An image shows its path alone — a picture has no reading position. A page
opened in the browser shows its title, or its path when it came from a file on
disk. A folder listing shows the folder. Narrow the window and the leading
folders drop away before the file name does, so the name never disappears.

A =•= after the name means unsaved changes. Plans never show one — they are
saved for you — but nothing saves a Markdown note you have edited, so there it
is worth having.

The heading path, and the open-task count beside it, stay where they mean
something: files that are part of your planning set. The documentation you are
reading, =config.org= and the capture queue are all Org files and none of them
gets one.

* Jumping around
- =C-c p f= — open a *recent file* (=recentf=).
- =C-c p i= — *imenu*: jump to a heading in the current file by name.
- =C-s= — *Swiper* incremental search within the current buffer (see
  [[file:Emacs-basics.org][Emacs basics]]).
- =s-r= — search across the whole project with ripgrep
  (=counsel-projectile-rg=).

* Under the hood / Customize
- The file tree (built on =treemacs=) is =lisp/ps-file-tree.el=, with its icon
  theme in =lisp/ps-file-tree-icons.el=. Its ignore list, layout
  (=ps/file-tree-hide-root=, =ps/file-tree-top-level-spacing=,
  =ps/file-tree-bold-top-level=, =ps/file-tree-root-mode=), file following
  (=ps/file-tree-follow-current-file=) and file sets are in =config.org= →
  /File Tree/ and in your =workspace.org=. Automatic refresh after a
  =git-sync= pull is a call to =ps/file-tree-refresh= from
  =lisp/ps-git-sync.el=; auto-refresh on disk changes is treemacs's built-in
  =treemacs-filewatch-mode=, enabled in =config.org= → /=treemacs= file
  tree/, with =ps/file-tree-node-lookup-setup= there teaching treemacs to
  find a file's line by path, since the tree no longer spells the file name
  out. =ps/file-tree-refresh= is also the manual full refresh behind the
  header-line button.
- To go back to the older shape — each top-level folder its own bold root — set
  =ps/file-tree-root-mode= to ='subdirs=. Files sitting directly in the Org base
  directory are then not shown anywhere, because treemacs cannot nest one
  project inside another.
- The icon-vs-name click behaviour is =ps/file-tree-click= /
  =ps/file-tree--click-label= in =lisp/ps-file-tree.el=.
- Holding the tree's width steady across Emacs-window resizes is
  =ps/file-tree-width-setup= in =lisp/ps-file-tree.el=, called from
  =config.org= → /=treemacs= file tree/ alongside =treemacs-width=, which sets
  the width the tree first opens at.
- The split-toggle command is defined in =config.org= → /Keybindings & Menu/.
- Back and forward are =lisp/ps-nav.el= (=ps/nav-history-limit= and the two
  glyphs in =config.org= → /Settings/ → /Navigation history/); the face a
  button takes under the mouse is =ps/nav-button-hover=. What opening a file of
  a given kind does is =lisp/ps-open.el=, driven entirely by =ps/open-handlers=
  in =config.org= → /Settings/ → /Opening files/. Folder browsing and the
  Markdown reading view are =config.org= → /Browsing a folder/ and /Reading
  Markdown/, with the listing's icons and sizes in =lisp/ps-dired.el=
  (=ps/dired-decorate-listing=, =ps/dired-size-width=).
- That one click follows a link — rather than two — is =ps/open-down-click= in
  =lisp/ps-open.el=: the folder listing, a Markdown note and the capture queue
  act on the press of the button rather than its release. =config.org= → /One
  click follows a link/ covers the rest of Emacs.
- The window title and mode line are =lisp/ps-mode-line.el=. A plan's short name
  is built by =ps/mode-line--display-name= and everything else by
  =ps/mode-line--generic-render=; =ps/mode-line-separator= sets the separator and
  =ps/mode-line-modified-indicator= the unsaved marker, both in =config.org= →
  /Settings/ → /Mode line/. How same-named files are told apart is Emacs's
  =uniquify-buffer-name-style=, pinned in =config.org= → /Package Management/.
