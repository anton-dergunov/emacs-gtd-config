This page walks through a full setup on macOS, Linux, and Windows. For a
two-minute version, see the [[file:../README.md][README]].

* 1. Install Emacs
Install [[https://www.gnu.org/software/emacs/download.html][Emacs]] — version 29 or newer is recommended (this config uses
=--init-directory= and other recent features).

- *macOS:* see the next section — a stock build freezes; build a patched one
  instead.
- *Linux:* use your package manager, e.g. =sudo apt install emacs= or
  =sudo dnf install emacs=.
- *Windows:* download the installer from a [[https://www.gnu.org/software/emacs/download.html][GNU mirror]].

** macOS: build Emacs with the freeze fix
On macOS, Emacs 30 can freeze outright: the window stops accepting keyboard and
mouse input and never recovers, so the only way out is Force Quit. Minimising
the window while a background task is running is enough to trigger it, and this
config's automatic Git sync counts as one — so it can happen several times a
day, and every freeze costs you the session.

The bug is in Emacs itself, not in this configuration. It affects every stock
macOS build, including [[https://emacsformacosx.com/][emacsformacosx.com]] and =brew install --cask emacs=. The
fix is two files in this repository, and you need both — the first on its own
still leaves a window in which Emacs can freeze:

- =patches/emacs-30-ns-appdefined-windownumber.patch= stops Emacs from
  addressing its own wake-up event to a window that does not exist.
- =patches/emacs-30-ns-appdefined-retry.patch= makes Emacs retry that wake-up,
  so a single lost one no longer hangs it permanently. Losing one turns out to
  be possible even when the window is valid — for instance while a second frame
  is taking focus.

[[https://github.com/d12frosted/homebrew-emacs-plus][emacs-plus]] builds Emacs from source, so it can apply the patches for you:

#+begin_src bash
brew tap d12frosted/emacs-plus

mkdir -p ~/.config/emacs-plus
cat > ~/.config/emacs-plus/build.yml <<'YAML'
patches:
  - ns-appdefined-windownumber:
      url: ~/.emacs.d/patches/emacs-30-ns-appdefined-windownumber.patch
      sha256: 319013a5587df554f81ef07ee25d678dcc4d169349d938b4164673b71d340d58
  - ns-appdefined-retry:
      url: ~/.emacs.d/patches/emacs-30-ns-appdefined-retry.patch
      sha256: 48c4577d5e49a74a40effe217cdd392bd30f6b5ca7139ef5e10cfa2c53a4c0fe
YAML

brew install --build-from-source d12frosted/emacs-plus/emacs-plus@30
open -n /opt/homebrew/opt/emacs-plus@30/Emacs.app
#+end_src

=build.yml= is emacs-plus's own extension point, so the patches are re-applied
automatically every time you rebuild — you never edit the formula. Adjust each
=url= if this repository is not at =~/.emacs.d=; a wrong path fails the build
with "Local patch file not found", so it cannot silently do nothing. Change a
patch file and the build stops on a checksum mismatch until you update its
=sha256=.

To confirm that the Emacs you are running really has both fixes:

#+begin_src bash
EMACS=/opt/homebrew/opt/emacs-plus@30/Emacs.app/Contents/MacOS/Emacs
lldb --batch -o "disassemble -n ns_send_appdefined" -o quit "$EMACS" | grep -c keyWindow
lldb --batch -o "disassemble -n ns_read_socket_1"  -o quit "$EMACS" | grep -c scheduledTimer
#+end_src

Each command should print a non-zero count. A =0= means that fix is not in.

*** Two traps when you rebuild later
- Use =brew uninstall= and then =brew install= — not =brew reinstall=. If the
  final linking step fails, and it does whenever symlinks from an older Emacs
  are still in =/opt/homebrew/bin=, =brew reinstall= quietly restores the
  previous build. You are then running an unpatched Emacs that looks freshly
  installed, which is why the check above is worth running.
- Homebrew compiles with =-Os= (optimised for size). To get =-O2= instead, add
  =cflags << "-O2"= near the top of the =cflags= list in the formula at
  =$(brew --repository)/Library/Taps/d12frosted/homebrew-emacs-plus/Formula/emacs-plus@30.rb=.
  Homebrew emits its own flags before these, so this one wins.
  Note that =brew update= silently reverts the edit.

*** What the patch does
Emacs pumps the macOS event loop by posting itself a private "wake up" event
and waiting for it to come back. That event is addressed to the application's
main window, and while the window is minimised there is no main window — so the
event is addressed to nothing, macOS discards it, and Emacs waits forever.
Nothing retries, and the timer that could have rescued it has already been
cancelled, so a single lost event wedges Emacs permanently. The patch addresses
the event to a window that actually exists.

* 2. Install ripgrep
[[https://github.com/BurntSushi/ripgrep][ripgrep]] powers fast in-project search.

#+begin_src bash
# macOS
brew install ripgrep

# Ubuntu/Debian
sudo apt install ripgrep
#+end_src

* 3. Get the configuration
Clone this repository as your Emacs configuration directory:

#+begin_src bash
git clone https://github.com/anton-dergunov/emacs-gtd-config.git ~/.emacs.d
#+end_src

On Windows the directory is usually
=C:\Users\<CURRENT_USER_NAME>\AppData\Roaming\.emacs.d=.

#+begin_quote
*Already have an `~/.emacs.d`?* Back it up first (=mv ~/.emacs.d ~/.emacs.d.bak=).
You can also run this config from any directory without touching =~/.emacs.d= —
see [[file:Developing.org][Developing & extending]].
#+end_quote

* 4. Point it at your Org files
All of your tasks and notes live in one base directory that you choose.

1. Copy =local.el.template= to =local.el= in the config directory.
2. Set =my-org-base-directory= to where you want your Org files. A folder inside
   Dropbox, iCloud, or another sync service keeps them available on every
   device.

To explore before committing to a layout, point it at the bundled example:

#+begin_src elisp
(setq my-org-base-directory
      (expand-file-name "samples/realistic/" user-emacs-directory))
#+end_src

Every =.org= file under that directory feeds the agenda, at any depth, so you
are free to organize it however you like. See [[file:Planning-setup.org][Planning setup]] for a suggested
layout and for the handful of names that are skipped.

* 5. First launch
Start Emacs. On the first run it downloads its packages into =elpa/= (this takes
a minute). When it settles, press =C-c p a= to open the agenda.

Optionally pre-download packages from the command line instead:

#+begin_src bash
emacs --batch -l ~/.emacs.d/init.el
#+end_src

* 6. Install the icon font (recommended)
Category icons — in the agenda and the file tree — are drawn from Google's
*Material Symbols Outlined* font. There are no per-icon image files to manage;
each icon is a font glyph, sized to your text so it stays aligned everywhere.

1. Download *Material Symbols Outlined* from [[https://fonts.google.com/icons][Google Fonts]] ("Download
   family") or the [[https://github.com/google/material-design-icons/tree/master/variablefont][google/material-design-icons]] repo.
2. From the archive, install only
   =Material_Symbols_Outlined/static/MaterialSymbolsOutlined-Regular.ttf= (the
   plain "Regular" static file — not a "Filled" or =*pt-*= variant).
3. Install it:
   - *macOS:* double-click the =.ttf= and click *Install Font* (or drop it in
     =~/Library/Fonts/=).
   - *Linux:* copy it into =~/.local/share/fonts/=, then run =fc-cache -f=.
   - *Windows:* right-click the =.ttf= and choose *Install*.

Without the font, everything still works — the file tree falls back to simple
folder/file icons. Assigning icons to your own categories is covered in
[[file:Customization.org][Customization & appearance]].

* 7. Install spell-check libraries (optional)
Org buffers get a quiet, multilingual typo checker. It needs the =enchant=
library plus a dictionary for each language you write in.

#+begin_src bash
# macOS
brew install enchant          # also pulls in hunspell
xcode-select --install        # C compiler for the module (skip if installed)

# Ubuntu/Debian
sudo apt install enchant-2
#+end_src

On macOS, English and several other languages work out of the box via the
system speller; Russian and stricter checking need Hunspell dictionary files.
If =enchant= isn't installed, the config still loads — typo checking simply
stays off. Full details, including which languages are enabled and how to add
dictionaries, are in [[file:Customization.org][Customization & appearance]].

* Under the hood / Customize
- The base directory and module loading happen in =config.org= ("Bootstrap"
  section) via =local.el=.
- The macOS freeze fix is =patches/emacs-30-ns-appdefined-windownumber.patch=
  plus =patches/emacs-30-ns-appdefined-retry.patch=; their headers record the
  full diagnosis. They are applied at build time through
  =~/.config/emacs-plus/build.yml=, not by this configuration at runtime.
- The dev launcher =scripts/run_emacs_dev.sh= sets all of this up automatically
  for testing — see [[file:Developing.org][Developing & extending]].
